# ロードマップ

GUI ツールキットで一般的に求められる機能のうち、naui (v0.10.0 時点) にまだ無いものを
洗い出し、優先度を付けたものです。

各項目に書いたネイティブの対応物は見立てです。着手するときに、4 環境
(OS とツールキットのバージョンを含む) で確かめ直します。

## 優先度の決め方

1. **4 環境にネイティブの対応物があるか**。naui の方針に合うかどうかなので、
   いちばん重く見ます。1 環境に無いものは、その差を[既知の制限](known-limitations.md)
   へ書くだけで済むかで判断します。
2. **それが無いと、ふつうのアプリですぐ困るか**。
3. **ほかのツールキットでどれだけ広く備わっているか**。
4. **実装の重さと、ほかの項目の土台になるか**。

適応レイアウトの作業 (`Stack::set_orientation`、Windows の `Stack` を `Grid` へ
移すこと、`Sidebar` の自動折りたたみなど) は別に進めているので、ここには
含めません。

## P0: すぐやる

小さく、無いと困り、4 環境に対応物があるもの。

- [ ] **入力欄の `on_submit`** (`TextInput`、`PasswordInput`、`NumberInput`)。
      Enter での確定は、どのフォームでも最初に要ります。`SearchInput` で扱った
      「変換中の Enter は数えない」をそのまま使えます。
- [ ] **フォーカスの出入りの通知** (`on_focus_change`)。入力の検証や、欄を
      離れたときの保存に使います。
- [ ] **ウィンドウの状態の操作**。位置、最大化、最小化、全画面、大きさを
      変えられるかどうか、その状態の取得です。Web は Fullscreen API だけ当て、
      ほかは対応しないと書きます。
- [ ] **`List` の右クリックとダブルクリック**。右クリックは `PopupMenu::open_at`
      と組み合わせて、行ごとの文脈メニューにします。
- [ ] **`Canvas` のホイールと、マウスボタンの区別**。`PointerEvent` に足すだけで、
      拡大縮小やパン操作の土台になります。

## P1: 次にやる

中くらいの重さで、要望が多いもの。

- [ ] **入れ子のメニュー、チェック付きのメニュー項目、ファンクションキーの
      ショートカット** (`MenuBar` と `PopupMenu`)。4 環境ともネイティブで持っていて、
      いまは naui の側だけの制限です。
- [ ] **ファイルのドロップを受け取る** (OS から部品やウィンドウへ)。
      `registerForDraggedTypes`、`GtkDropTarget`、`AllowDrop`、DOM の `drop`。
- [ ] **ポップオーバー** (部品に付けて、任意の中身を出す)。`NSPopover`、
      `GtkPopover`、`Flyout`、HTML の `popover` 属性。Web で部品の脇に出すには
      CSS の anchor positioning が要るので、ブラウザごとの対応を調べてから決めます。
- [ ] **任意の中身を置けるダイアログ**。`ContentDialog`、`AdwDialog`、シート、
      `<dialog>`。ポップオーバーと作りの多くを共有できます。
- [ ] **画像の入力元を増やす** (メモリ上のバイト列、SVG、ピクセルバッファ)。
      いまはパスと URL だけです。Web は Blob URL で済みます。
- [ ] **書式付きテキスト** (太字、色、リンクを 1 行の中で混ぜる)。
      `NSAttributedString`、Pango markup、`TextBlock.Inlines`、`<span>`。
- [ ] **`List` の大量行の絞り込み**。`Table` の仕組み (`row_window`) を `List`
      にも広げます。
- [ ] **回転するインジケーター** (Spinner)。`NSProgressIndicator`、`AdwSpinner`、
      `ProgressRing`。DOM には対応物が無いので、Web は不確定の `<progress>` で
      出して差を書きます。
- [ ] **区切り線と、枠付きのまとまり**。`NSBox`、`GtkSeparator` / `GtkFrame`。
      WinUI には単体の区切り線が無いので、何で代用するかを先に調べます。
- [ ] **ボタンの役割** (主ボタン、破壊的な操作)。macOS の `hasDestructiveAction`、
      GTK の `suggested-action` / `destructive-action`。WinUI は主ボタンだけ
      (`AccentButtonStyle`)、Web は対応物が無いので差を書きます。

## P2: 余裕があればやる

重いか、対応する環境が限られるもの。

- [ ] **テストの仕組みを環境をまたいで公開する**。いまある試験用の API
      (`click`、`activate` など) を、アプリを作る人向けにまとめます。
- [ ] **`Canvas` の語彙を広げる** (画像、クリップ、回転や拡大、グラデーション)。
      文字の幅の計量は WinUI で難しいので後回しにします。
- [ ] **`Table` の列幅のドラッグを Windows と Linux でも効かせる**。Linux は
      `GtkColumnView` にネイティブの機能があり、Windows は自前の表なので重いです。
- [ ] **`Tree` の複数選択と、項目に部品を置くこと**。
- [ ] **Windows と Linux の `Grid` で `Track::Fill` の重みを効かせる**。
- [ ] **デスクトップ通知**。macOS はバンドル、Linux は `.desktop` ファイル、
      Windows は登録が要るので、配り方の条件ごと書く必要があります。
- [ ] **クリップボードで画像を扱う**。
- [ ] **ウィンドウの位置と大きさの保存と復元**。P0 のウィンドウの状態の操作が
      できてから取りかかります。
- [ ] **ダイアログとトーストの制限を緩める** (ボタンの数、トーストの順番待ち、
      出る位置)。

## P3: 調べてから決める

方針に合うか、要るかがまだはっきりしないもの。

- [ ] **トレイアイコン**。GTK4 には無く DBus の StatusNotifierItem が要ります。
      WinUI にも無いので Win32 で作ることになり、Web には対応物がありません。
- [ ] **部品どうしのドラッグ&ドロップ** (`List` や `Tree` の並べ替え)。
- [ ] **印刷**。
- [ ] **単一起動、ファイルの関連付け、URL スキーム**。配り方とパッケージングに
      強く結び付きます。
- [ ] **フォントの選択と、カレンダーを常に表示する部品**。
- [ ] **右から左へ書く言語のレイアウトと、翻訳の仕組み**。ネイティブがどこまで
      自動で直すかを、まず確かめます。
- [ ] **WebView、コードエディター、Markdown の表示、グラフ**。本体ではなく
      別クレートで作るのが向いていそうです。

## やらないこと

naui の方針と合わないもの。

- **部品ごとの自由な色や角丸の指定、アニメーション、自分で描く部品、GPU との
  統合**。ウィジェットを自前で描画しないという方針に反します。
- **宣言的な UI の記法、ホットリロード**。作るとしても本体ではなく、上に載せる
  別クレートにします。
- **iOS、Android、組み込み機器**。スマホ向けのバックエンドが無く、CI でも
  確かめられないため保留にしています。
